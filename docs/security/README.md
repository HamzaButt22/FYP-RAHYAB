# Security, compliance and data governance

| Document | What it covers |
|---|---|
| [`SECURITY.md`](SECURITY.md) | **Threat model:** assets, attackers, STRIDE threats and controls for each component, trust boundaries, secure coding rules, security testing, incident response, responsible disclosure |
| [`COMPLIANCE.md`](COMPLIANCE.md) | **Compliance mapping:** the PDP Bill (draft), PECA 2016, Cloud First policy, Google Play policies, the ICO Children's Code, research ethics, OWASP, WCAG and licences, each mapped to its control, requirement, evidence and status |
| [`DPIA.md`](DPIA.md) | **Data Protection Impact Assessment:** processing, lawful basis, necessity, 10 risks with controls, consultation, sign-off |
| [`DATA_GOVERNANCE.md`](DATA_GOVERNANCE.md) | **Policies:** data classification, the retention schedule, encryption and key management, access control, the data inventory for the Play Data safety form, breach handling |

The requirements behind these documents are SRS NFR-36–49, NFR-66–72 and FR-05, FR-09, FR-10, FR-84 and FR-85. The tests are in `docs/testing/TEST_CASES.md` §2.7.
